XAMAuxData.AuxTag — Type
AuxTag(::AbstractString)
AuxTag(::Char, ::Char)
AuxTag(::UInt8, ::UInt8)

The type of a key of Auxiliary. This type is a lightweight two-character AbstractString, and validates that the key is of appropriate format. Like other strings, it compares and hashes equal to strings with the same content, e.g. isequal(AuxTag("AB"), "AB"). Auxiliary can also be indexed using other strings as keys, which will be converted to AuxTag.

To construct an AuxTag of value "AB", you can use:

  • AuxTag("AB")
  • AuxTag('A', 'B')
  • AuxTag(UInt8('A'), UInt8('B'))
  • try_auxtag(UInt8('A'), UInt8('B'))

Throw an AuxException if the resulting AuxTag does not conform to the regex r"^[A-Za-z][A-Za-z0-9]$(Expr(:incomplete, Base.Meta.ParseError("ParseError:\n# Error @ none:1:3\n\".\n# └ ── unterminated string literal", Base.JuliaSyntax.ParseError(Base.JuliaSyntax.SourceFile("\".", 0, "none", 1, [1]), Base.JuliaSyntax.Diagnostic[Base.JuliaSyntax.Diagnostic(3, 2, :error, "unterminated string literal")], :string))))

Examples

julia> AuxTag("AC")
AuxTag("AC")

julia> AuxTag('k', 'w')
AuxTag("kw")

julia> AuxTag("1C") # invalid tag
ERROR: Invalid AuxTag. Tags must conform to r"^[A-Za-z][A-Za-z0-9]$".
[...]

XAMAuxData.Hex — Type
Hex(v::AbstractVector{UInt8}) <: AbstractVector{UInt8}

Wrapper type around a byte vector. When this type is assigned to an Auxiliary, it is encoded as a hex value (type tag H) as opposed to a raw byte array ( type tag B). Conversely, H values are loaded as Hex{Memory{UInt8}}, such that writing a loaded value back preserves its type.

Hex is a minimal AbstractVector{UInt8}: it only implements size, axes and getindex, so most operations on it hit generic, potentially slow fallback methods. For anything performance sensitive, use parent(hex), which is guaranteed to return the wrapped vector, i.e. a V for a Hex{V}.

julia> aux = SAM.Auxiliary(UInt8[], 1);

julia> aux["AB"] = Hex([0xae, 0xf8, 0x6c]);

julia> String(MemoryView(aux))
"AB:H:AEF86C"

julia> aux = BAM.Auxiliary(UInt8[], 1);

julia> aux["AB"] = Hex([0xae, 0xf8, 0x6c]);

julia> String(MemoryView(aux))
"ABHAEF86C\0"
XAMAuxData.Errors.Error — Type
Error

Enum type representing corrupt auxiliary data. The errors are nonexhaustive - more might be added in a non-breaking release. See is_well_formed for the distinction between malformed and invalid data.

When loading an invalid value, e.g. with getindex, get, iteration or try_get, one of these errors is returned instead of the value:

  • InvalidTypeTag (SAM): A value with an unknown type tag
  • InvalidArrayEltype (SAM): A B value with a missing or unknown element type
  • InvalidChar: An A value that is not a single character in '!':'~'
  • InvalidInt (SAM only): An i value that is not a decimal integer in the range of Int64
  • InvalidFloat: An f value that is NaN or infinite, or, in SAM, which is not a decimal number representable as a finite Float32
  • InvalidString: A Z value containing a byte not in re"[ !-~]"
  • InvalidHex: An H value with an odd number of symbols, or a symbol not in re"[0-9A-F]"
  • InvalidArray: A B value containing a NaN or infinite float, or, in SAM, which is not a comma-separated list of numbers representable by its element type

If the auxiliary is malformed, most functions throw one of these errors wrapped in an AuxException, whereas try_get returns it:

  • TooShortMemory: A field is too short, e.g. because it is truncated
  • InvalidAuxTag: A field's key is not a valid AuxTag
  • NoColons (SAM only): A field is not of the form XX:T:value
  • NoNullByte (BAM only): A Z or H value is not null-terminated
  • InvalidTypeTag (BAM): A value with an unknown type tag
  • InvalidArrayEltype (BAM): A B value with an unknown element type

In BAM, unknown type tags make the auxiliary malformed, because the length of the value cannot be determined.

Errors are also thrown wrapped in an AuxException when attempting to write an invalid key or value, e.g. InvalidInt when writing an integer outside [-2^31, 2^32).

See also: Errors

XAMAuxData.SAM.Auxiliary — Type
SAM.Auxiliary{T <: AbstractVector{UInt8}} <: AbstractDict{AuxTag, Any}

Lazily loaded AbstractDict representing the auxiliary data fields of a SAM record. Immutable aux's can be constructed with Auxiliary(x) for any x with MemoryView(x) defined. Mutable aux data is constructed with Auxiliary(x::Vector{UInt8}, start::Int), where start gives the first index of the used data in x - all data before start will be ignored and never modified.

Examples

julia> immut = SAM.Auxiliary("KJ:i:-1	AB:Z:abc");

julia> immut["KJ"]
-1

julia> haskey(immut, "AB")
true

Extended help

Since fields of Auxiliary are lazily loaded, auxiliaries may contain invalid data even after successful construction. Auxiliary operates with two distinct notions of invalid data - malformedness and invalidness. See is_well_formed for their definitions.

Values loaded from a mutable Auxiliary may be views into its data, and are invalidated by mutating the Auxiliary. See the section "Values may be views into the auxiliary" in the documentation.

Keys are converted to AuxTag by all methods, including lookups such as haskey and get. Unlike Dict, which returns false from haskey for a key of the wrong type, these methods throw if the key cannot be converted to a valid AuxTag. Such a key is a type error by the caller: Use try_auxtag to check keys of unknown validity.

XAMAuxData.is_well_formed — Function
is_well_formed(aux::AbstractAuxiliary; check_duplicates::Bool = true) -> Bool

Check if the auxiliary is well formed. AbstractAuxiliary distinguishes two ways their data can be incorrect: If the data is corrupted such that no loaded value can be trusted without checking the whole auxiliary, we say the auxiliary is malformed. This is the case if it is not possible to identify the key, or start/end of the encoded data of the value for a key/value pair, or if a key occurs more than once. Accessing values, or iterating such an auxiliary may throw an exception, but is not guaranteed to. For example, loading a duplicated key may return any of its values. This notion of malformedness is what this function checks for.

Checking for duplicate keys has a significant cost relative to the rest of this function. If check_duplicates is false, duplicate keys are not checked for. Only do this if you know aux has no duplicate keys, e.g. because its data was produced by a trusted source.

Alternatively, if the keys and encoded values can be identified, but the encoded values are corrupt and the value cannot be loaded, we say the auxiliary is invalid. Such auxiliaries can be iterated over, and the values can be loaded, although the loaded value will be of type XAMAuxData.Error. This can be checked for with isvalid. Valid auxiliaries are always well-formed.

Examples

julia> aux = SAM.Auxiliary("KM:i:252\tAK::C"); # bad key

julia> is_well_formed(aux)
false

julia> aux["KM"] # loading a value may error
252

julia> aux["AK"] # loading a value may error
ERROR: Invalid SAM tag header. Expected <AuxTag>:<type tag>:, but found no colons.
[...]

julia> aux = SAM.Auxiliary("AB:Z:αβγδ\tCD:f:-1.2"); # bad value encoding

julia> (is_well_formed(aux), isvalid(aux))
(true, false)

julia> aux["AB"] # note: numerical value of enum is not API
InvalidString::Error = 9

julia> aux = SAM.Auxiliary("AB:i:1\tAB:i:2"); # duplicate key

julia> is_well_formed(aux)
false

julia> is_well_formed(aux; check_duplicates = false)
true
XAMAuxData.try_get — Function
try_get(
    aux::AbstractAuxiliary,
    key
)::Union{Nothing, XAMAuxData.Error, Any}

Convert key to AuxTag, then get the value associated with key in aux, without throwing on corrupt data. Return nothing if key is not present, and an XAMAuxData.Error if the value is invalid, or if aux is malformed before key is found.

Unlike checking is_well_formed before indexing, this only scans the auxiliary data until key is found. Hence, if key is found, it is not checked whether data after key is malformed, for example, whether key occurs again.

Examples

julia> aux = SAM.Auxiliary("KM:i:252	AB:Z:αβγδ	AK::C");

julia> try_get(aux, "KM")
252

julia> try_get(aux, "AB") # invalid value
InvalidString::Error = 9

julia> try_get(aux, "XX") # malformed before key is found
NoColons::Error = 2

julia> try_get(SAM.Auxiliary("KM:i:252"), "XX") === nothing # key not present
true

See also: is_well_formed

Base.isvalid — Method
isvalid(aux::AbstractAuxiliary; check_duplicates::Bool = true) -> Bool

Check if the auxiliary is well formed, and that all the values can be loaded without returning an XAMAuxData.Error. If check_duplicates is false, duplicate keys are not checked for. See is_well_formed for details.

Examples

julia> aux = SAM.Auxiliary("AB:i:not an integer");

julia> is_well_formed(aux)
true

julia> isvalid(aux)
false

See also: is_well_formed

XAMAuxData.setindex_nonexisting! — Function
setindex_nonexisting!(dst::MutableAuxiliary, val, key) -> dst

Same as dst[key] = val, but assumes that key is not present in dst.

Warning

If key is in dst, this will result in a malformed dst with a duplicate key, which may cause invalid behaviour.

Examples

julia> v = SAM.Auxiliary(UInt8[], 1);

julia> setindex_nonexisting!(v, 'k', "BA")
1-element XAMAuxData.SAM.Auxiliary{Vector{UInt8}}:
  "BA" => 'k'
